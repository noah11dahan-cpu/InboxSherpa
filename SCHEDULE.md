Week 1 — Core pipeline + first digest demo (end-to-end MVP) 
Day 1 — Repo scaffold + foundations Create repo structure exactly like your blueprint. Set up pyproject.toml (FastAPI, SQLAlchemy, Alembic, pytest, httpx, pydantic, uvicorn). Add .env.example, Makefile targets (make dev, make test, make fmt, make up). Stand up docker-compose.yml with api, db, worker (worker can be a no-op initially). Deliverable: docker compose up boots API + Postgres; /health returns OK. 
Day 2 — Data model + migrations Implement SQLAlchemy models: User, Message, Thread (optional minimal), Cluster, SuggestedAction. Add Alembic migration + seed dev DB (one demo user). Define the generic message schema (sender, subject, body, timestamp, channel, external_id, status). Deliverable: database tables created + a seed script inserts demo user. 
Day 3 — Importer (JSON → DB) + unit tests Implement services/importer.py to load data/sample_inbox.json. Add /messages/import endpoint (accept file path or raw JSON in dev). Write unit tests for importer: validates required fields de-dupes by (user_id, external_id) or hash Deliverable: import 200–500 sample messages reliably; pytest green. 
Day 4 — Clustering v1 (baseline, deterministic) Implement services/clustering.py: Start simple: TF-IDF + KMeans (or sklearn agglomerative), or even keyword-based fallback if you want zero heavy deps. Store cluster assignments in Clusters table. Add /digest/today placeholder that returns clusters + message counts. Deliverable: import → cluster → return cluster list with titles like “Promos / School / Bills”. 
Day 5 — Summarizer contract (no LLM yet) + schema validation Define the structured JSON output you’ll eventually get from an LLM: cluster_title, summary_bullets, urgency, suggested_actions[], confidence Implement a mock summarizer that generates summaries heuristically (top senders/subjects). Add JSON schema validation tests so you can swap in a real LLM later without breaking. Deliverable: each cluster now has a “summary object” that passes schema tests. 
Day 6 — Minimal UI: “Today’s Digest” page Add a basic frontend (choose one): FastAPI + Jinja templates (fastest) or a tiny React/Vite page if you prefer UI shows: cluster cards (title, count, urgency, summary bullets) click cluster → show included messages Deliverable: first real “Generate today’s digest” experience. 
Day 7 — End-to-end integration test + weekend demo v0 Write tests/test_digest_flow.py: import → cluster → digest endpoint returns expected structure Add “demo seed” dataset tuned for nice clustering (School/Promos/Work/Bank). Deliverable: end-to-end MVP works locally with one command. Milestone at end of Week 1: MVP digest generated from JSON with clustering + summaries + basic UI. 
Week 2 — Actions, feedback loop, observability, evals, and scale polish 
Day 8 — Suggested actions engine (rule-based v1) Implement services/actions.py: Rules like: “Promotions” cluster → suggest archive_all “Calendar / deadlines” → suggest snooze or reply_with_template Store suggestions in SuggestedActions with status: proposed/accepted/rejected. Deliverable: digest includes suggested actions per cluster. 
Day 9 — Actions API + UI accept/reject Add /actions/apply endpoint: marks messages as archived/snoozed/replied (status change in DB only for MVP) logs acceptance/rejection UI buttons: Accept / Reject per suggestion. Deliverable: click “Archive 5 promos” → message statuses update and disappear from “inbox” view. 
Day 10 — Worker orchestration (periodic jobs) Implement workers/scheduler.py: periodic “fetch new messages” (still from JSON in MVP) run clustering + summarization Ensure worker is separately runnable via Docker. Deliverable: docker compose up runs API + worker; digest updates automatically. 
Day 11 — Observability + metrics page Add lightweight metrics: messages processed today cluster count action acceptance rate average clustering runtime Expose /metrics (simple JSON is fine) + UI “Metrics” page. Deliverable: recruiter can see “messages processed” and “actions accepted.” 
Day 12 — Load testing + performance guardrails Create a generator for 5k messages (synthetic but realistic). Implement a batch clustering mode: time the pipeline store timings Add a load test script (pytest marker or a standalone script) that asserts: 5k messages cluster + summarize within ~30s on your machine (or set a realistic threshold). Deliverable: performance story is credible and measured. 
Day 13 — AI eval harness (offline) + rubric scoring Build evals/: 100 test clusters with “good vs bad” summaries (stored fixtures) scoring harness that checks: relevance (keyword overlap / semantic similarity proxy) brevity constraints urgency sanity checks Add a simple CLI: python -m evals.run Deliverable: reproducible eval output + target thresholds printed. 
Day 14 — README polish + 3-minute demo script + “real Gmail later” design Write a strong README: architecture diagram (ASCII is ok) how to run (one command) how clustering works privacy stance (no auto-archive; delete data; minimal scopes) roadmap for Gmail OAuth integration (read-only scope) Add a /demo route or a “Demo Mode” button that: imports sample data generates digest guides the click path Deliverable: ready to share repo + polished demo narrative.
